## B-01. Фолбэк `usePaginationFade` по построению не эквивалентен CSS-классу

> **Статус: ИСПРАВЛЕНО** по твоему решению (вариант 1: `1.4` → `1.5`), коммит
> `fix(pagination)`. Ниже — исходное описание. Отдельно показательно, что
> `tsc` и весь существующий набор тестов остались зелёными: этот фолбэк не был
> покрыт ничем, поэтому и разошёлся незаметно. Комментарий в
> `tests/usePaginationFade.test.tsx`, называвший старое значение, поправлен
> тем же коммитом.

**Где:** `src/components/Carousel/client/modules/Pagination/basic/usePaginationFade.ts:39-40`
против `src/components/Carousel/client/modules/Pagination/basic/Pagination.module.scss:13-15`

**Что не так.** Биндинг читает внешний вид точки из CSS-переменных, чтобы
анимация заканчивалась ровно в том состоянии, которое дальше держит класс
`.dotActive`. На случай нечитаемой переменной есть JS-фолбэки:

```ts
const FALLBACK_INACTIVE: DotVisualState = { opacity: 0.2, scale: 1 };
const FALLBACK_ACTIVE:   DotVisualState = { opacity: 0.8, scale: 1.4 };
```

CSS:

```scss
--pagination-dot-opacity:        0.2;   // совпадает
--pagination-dot-opacity-active: 0.8;   // совпадает
--pagination-dot-scale-active:   1.5;   // НЕ совпадает с фолбэком 1.4
```

Две из трёх величин синхронизированы точно, третья разошлась — это похоже на
дрейф при правке SCSS, а не на осознанное различие: смысл фолбэка в том, чтобы
подменять CSS, а не задавать другое состояние.

**Воспроизведение.** Фолбэк срабатывает только когда
`getComputedStyle(dot).getPropertyValue("--pagination-dot-scale-active")`
не парсится в число (`readVar` → `Number.parseFloat` → `NaN`). Практически:

1. **В браузере** — если переменную переименовать/удалить в SCSS (или точки
   отрендерены вне области, где переменная объявлена, — она объявлена на
   `.paginationWrapper`, значит на самих точках наследуется).
2. **В jsdom** — постоянно: jsdom для кастомных свойств обычно возвращает
   пустую строку, то есть в тестовой среде рабочим путём является **фолбэк**.

Наблюдаемый эффект: WAAPI-анимация точки доводит `scaleX` до 1.4, после
`settle` биндинг снимает инлайн-слой и точку подхватывает класс со `scaleX(1.5)`
— на переходе видна ступенька, замаскировать которую анимация как раз и должна.

**Цена.** Низкая в проде (путь недостижим при исправном SCSS), но именно этот
фолбэк — единственная защита контракта E-6 из `INVARIANTS.md`, и защищает он
неверным значением. Плюс он делает тестовую среду не эквивалентной браузерной.

**Предложение (на твоё решение), в порядке убывания моего предпочтения:**

1. Привести `FALLBACK_ACTIVE.scale` к `1.5` — одна цифра, восстанавливает
   заявленный смысл фолбэка.
2. Убрать числовые фолбэки совсем и не анимировать точку, если внешний вид не
   читается (класс справится сам) — честнее, но меняет поведение в jsdom, а
   значит и тестируемость модуля.
3. Оставить как есть и зафиксировать в комментарии, что фолбэк — «примерно
   похоже», а не «то же самое».

Правку не вносил.
