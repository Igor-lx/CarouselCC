# environment — чтобы задача не вставала на подтверждениях

Правила и инструменты переносятся копированием папки, а вот **среда — нет**: в
новом проекте нет ни списка разрешений, ни знания о том, какие команды его
обходят. Разница видна сразу: поставил задачу, отошёл — и вернулся к
запросу подтверждения, который стоит там с первой минуты. Этот файл существует,
чтобы такого не было ни в одном новом проекте.

Всё ниже — не рассуждение, а наблюдения, снятые на живой сессии. Где механизм
не установлен, так и написано.

## Что снимается списком разрешений

Рядом лежит [`settings.template.json`](./settings.template.json) — его кладут в
новый проект как `.claude/settings.json`. Список закрывает две группы:

- **команды проверок и работы:** `npm run …`, `npx vitest|eslint|tsc|prettier`,
  `npx stryker run`, `node .context/graph.mjs …`;
- **чтение названного файла:** `cat`, `head`, `tail`, `sed -n`, `wc`, `diff`,
  `od`, `ls`, а также `grep` по конкретному пути.

Записи сверяются по началу команды. Склейка через `&&` разрешения **не
наследует**: разрешённой должна быть каждая часть, поэтому `cd` в списке стоит
отдельно — без него любая команда вида `cd проект && npm test` будет спрашивать.

## Что списком НЕ снимается

**Обход дерева каталогов через оболочку спрашивает всегда.** Проверено прямым
опытом: `grep -n "…" src/app/App.tsx` проходит молча, а
`grep -rn "…" src/components/…/docs` требует подтверждения — и требует его даже
после того, как `Bash(grep *)` добавлен в список. То же ожидаемо для `find` по
дереву.

Механизм из сессии не виден, и выдавать догадку за факт тут нельзя. Наблюдаемое
правило простое и этого достаточно: **названный файл — проходит, обход дерева —
спрашивает.**

## Отсюда раздел труда, а не отказ от Bash

| Задача | Чем |
| --- | --- |
| Команды: сборка, тесты, линт, git, инструмент базы | Bash |
| Чтение конкретного файла по известному пути | Bash (`sed -n`, `head`, `cat`) или Read |
| Поиск по репозиторию, обход дерева | **инструмент Grep** — подтверждений не требует в принципе |
| Файл, который собираешься править | **только Read** |

Последняя строка — не вкус, а механика: `Edit` отказывается править файл,
который не был прочитан **инструментом** `Read` в этом же диалоге. Прочитал
через `cat` — на правку уйдёт лишний вызов. Так что Bash-чтение перед правкой
не экономит, а добавляет заход.

Выигрыша в скорости или в токенах у Bash-чтения нет: оболочка порождает процесс,
инструмент Grep запускает тот же поисковик напрямую, объём вывода сопоставим.
Единственная разница — где всплывает подтверждение.

## Мелочи среды, на которых спотыкаются молча

- **Рабочая папка Bash сбрасывается между вызовами.** Сессия может стартовать
  уровнем выше проекта, и тогда `git status` отвечает `not a git repository`.
  Писать `cd <проект> && …` либо абсолютные пути, а не полагаться на то, что
  предыдущий `cd` ещё действует.
- **Труба уничтожает код возврата.** `проверка | tail` возвращает результат
  `tail`, поэтому и `&&` после неё не спасает. Проверки прогоняются своим
  вызовом, их вывод читается, и только потом делается коммит.
- **`tail` срезает начало отчёта.** У инструментов, печатающих несколько
  секций, первая — самая важная (покрытие карты). Смотреть `head`, а не только
  `tail`, иначе легко объявить проверку отсутствующей.
- **Пустой ответ поисковика — ещё не отсутствие файлов.** Встречалось: `Glob`
  по `**/*.ts` возвращал пусто там, где `ls` файлы видит. Прежде чем делать
  вывод «этого нет», перепроверить другим способом.

## Концы строк — политика репозитория, а не настройка машины

Отдельный пункт, потому что портит он не сборку, а **правки**: на машине с
`core.autocrlf=true` рабочее дерево окажется в CRLF, и любая замена
многострочного фрагмента, ищущая по одному лишь `\n`, не найдёт ничего —
молча, без ошибки. Инструмент отчитается «готово», а файл останется прежним.

Лечится одним файлом в корне, до первого коммита:

```gitattributes
# Line endings are repository policy, not a per-machine setting: LF in the
# repository and in the working tree, whatever core.autocrlf happens to be.
* text=auto eol=lf

# Binary assets must never be touched.
*.png binary
*.jpg binary
*.jpeg binary
*.webp binary
*.avif binary
*.woff binary
*.woff2 binary
```

Заведённый позже, он не перепишет уже лежащие файлы сам: их придётся
переиндексировать. Отсюда «до первого коммита», а не «когда попадётся».

## Как посадить в новый проект

1. Создать в корне проекта папку `.claude/`.
2. Скопировать `settings.template.json` как `.claude/settings.json`.
3. Сверить пути в записях с проектом: если база знаний лежит не в `.context/`,
   поправить строку `node .context/graph.mjs *`; если менеджер пакетов не npm —
   заменить команды проверок на свои из `CLAUDE.md`.
4. Положить в корень `.gitattributes` по образцу выше — **до первого коммита**.
5. Проверить на месте: один `npm test` и один поиск по репозиторию. Если
   подтверждение всё же всплыло — команда в списке не покрыта, и её добавляют
   **до** того, как задача поставлена и человек отошёл.

Экран `/permissions` показывает, какое правило сработало. Из сессии он не виден,
поэтому смотреть его — работа человека, а не агента.
