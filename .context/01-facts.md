# 01-facts — то, чего нет ни в коде, ни в документации

Дополнение к [`00-map.md`](./00-map.md). Там — что делает каждый файл. Здесь —
**механически проверенные факты о проекте как о целом**. Всё получено скриптами,
не чтением.

## Что здесь читают целиком, а что смотрят по адресу

Файл длинный, и читать его весь перед каждой правкой не нужно. Целиком — только
то, без чего можно начать работу неверно; остальное открывают, когда вопрос
возник.

| Читать целиком, до работы | Зачем |
| --- | --- |
| «Как читать пути» | иначе сокращения в карте ведут не туда |
| A. Базовая линия | что считается зелёным и с какими числами сравнивать |
| B. Цикл импортов | их ровно один, и он ловушка при переносе файла |
| H. Решения по объёму | что уже решено и не обсуждается заново |
| J. Как перепроверить | какие команды вообще существуют |
| K. Ловушки окружения | каждая уже стоила времени |

| Смотреть по адресу | Когда |
| --- | --- |
| A2. Инструменты проверки | правишь конфиг линта или трогаешь `eslint-disable` |
| C. Радиус поражения | нужен масштаб правки — но живее `graph.mjs blast` |
| D. Мёртвые экспорты | удаляешь или переименовываешь экспорт |
| E, F. Дрейф и заявки доков | трогаешь `docs/**` или опираешься на их утверждение |
| G. Указатель документации | ищешь, где про это написано подробно |
| I. Проход «вырезать историю» | встретил ссылку на прошлые прогоны |

Разделы C и D дублируют то, что `graph.mjs` считает заново: в тексте они полезны
как картина, но при расхождении прав скрипт.

## Как читать пути в этом документе и в `00-map.md`

Пути сокращены и лежат на **разной** глубине — дописывать один общий префикс
нельзя:

| Сокращение | Реальный путь |
| --- | --- |
| `client/**` | `src/components/Carousel/client/**` |
| `docs/**` (architecture, adr, config) | `src/components/Carousel/client/docs/**` |
| `boundary/**`, `data-gen/**` | `src/components/Carousel/**` |
| `shared/**` | `src/shared/**` |
| `app/**`, `main.tsx`, `globals.scss` | `src/**` |
| `public/**`, `package.json`, `tsconfig*.json` | от корня репозитория |

⚠️ `docs/` — **не** в корне репозитория, а внутри `client/`. Якоря в коде
(`// See docs/architecture/motion.md`) указывают именно туда.

Отсюда и относительные импорты в коде: `../../../../shared` из
`client/motion/*` — это `src/shared`, а не папка внутри карусели.

(отсюда `!` после индексации), `exactOptionalPropertyTypes` (отсюда

(отсюда `void x` в тестах), `erasableSyntaxOnly`, `noFallthroughCasesInSwitch`,
`verbatimModuleSyntax` (отсюда `import type` везде).

## A2. Инструменты проверки (заведены после базовой линии)

| Файл | Что задаёт |
| --- | --- |
| `eslint.config.js` | flat config: `typescript-eslint` с типовой проверкой (`projectService`), `react-hooks`, `react-refresh`; форматирование целиком отдано Prettier через `eslint-config-prettier` |
| `.prettierrc.json` | `printWidth: 80`, двойные кавычки, `trailingComma: "all"`, `endOfLine: "auto"` |
| `.prettierignore` | `dist`, `coverage`, `node_modules`, `public`, `package-lock.json`, а также **все `*.md`**: markdown здесь — свёрстанная руками проза, Prettier только доливает в неё пустые строки |
| `.gitattributes` | `* text=auto eol=lf` — концы строк перестали зависеть от `core.autocrlf` машины (на этой он `true`, файлы в рабочем дереве были CRLF) |

**Три обоснованных исключения в конфиге линта, все с комментарием на месте:**

1. `@typescript-eslint/require-await` выключен в `**/tests/**`: React-`act`
   возвращает thenable только при async-скоупе, поэтому `async` без `await`
   внутри — требование API, а не оплошность.
2. `react-refresh/only-export-components` выключен в `client/modules/**`:
   слот-компоненты собираются как `Object.assign(Component, { slot })`, Fast
   Refresh такую форму не отслеживает, а форма — это контракт модуля.
3. `react-hooks/globals` и `react-hooks/refs` выключены в `**/tests/**`:
   фикстуры живут на модульном уровне и переприсваиваются между кейсами, а ref
   тест читает и подменяет намеренно. Оба правила описывают код компонентов.
4. PENDING больше нет: правило включено везде. Было шесть файлов.

**Что разобрано из PENDING и как:**

| Узел | Решение |
| --- | --- |
| `compositedRide` (оба форка) | райдер держится в состоянии: он владеет живой ручкой анимации, а memo/ref из рендера для этого не годится; смена контроллера — правка состояния во время рендера |
| `useSlideFetchReach` | стабильная ссылка на URL полосы — в состоянии с чистой сверкой `sameUrls`, вместо ref, который писали внутри `useMemo` |
| `useSlideRenderModel` | окно рендера и `layoutOrigin` — явное состояние с правкой во время рендера. Побочная выгода: идентичность окна теперь меняется только при смене границ, раньше на каждом рендере в покое рождался новый объект |
| `useCarouselPresentation` | кэш полос переехал в ref с ключом `origin:index`, поэтому синхронная инвалидация не нужна вовсе; чистка — в эффекте после коммита |
| `useCarouselState` | контекст редьюсера (`layout`, `config`, `isInstantMode`) переехал **в состояние**, конверт `ReducerEnvelope` удалён, фиксация — командой `SYNC_CONTEXT` во время рендера. Рефов в файле не осталось. См. `docs/adr/0004-reducer-owns-its-context.md`; он же поправляет ADR-001 (границ согласования теперь одна, а не две) |

**Точечные `eslint-disable` — все пять, посчитаны грепом:**

| Файл | Правило | Почему |
| --- | --- | --- |
| `slides/useSlideRenderModel.ts` ×2 | `react-hooks/immutability` | кэш идентичности `VirtualSlide`: без него вся колода перерисовывается дважды за поездку (CONSTRAINT в коде) |

## B. Циклическая зависимость — ровно одна

```
client/motion/index.ts
  → motion/useCarouselMotionExecution.ts
  → motion/useMotionRunner.ts
  → client/geometry/index.ts
  → geometry/useTrackBinding.ts
  → client/motion/index.ts      ← замыкание
```

**Механика:** `useTrackBinding` берёт из бочки `../motion` значения
(`keyframesAlongStops`, `startPinnedAnimation`) и тип `MotionPlanSource`;
`useMotionRunner` берёт из бочки `../geometry` тип `TrackBindingApi`.

**Почему сейчас не ломается:** обратное ребро (`useMotionRunner → geometry`) —
**только тип**, он стирается при компиляции, поэтому в рантайме цикла нет.
**Что это значит для правок:** любая правка, превращающая этот импорт в
значение, замкнёт настоящий рантайм-цикл (порядок инициализации модулей,
`undefined` при первом обращении). Разрывается тривиально — импортировать
`keyframesAlongStops`/`startPinnedAnimation` в `useTrackBinding` напрямую из
`shared`, минуя транзитную бочку `client/motion`.

## C. Радиус поражения: что ломает больше всего

Числа здесь не переписываются руками — они считаются:

```
node .context/graph.mjs blast              # весь список, по убыванию
node .context/graph.mjs blast domain/index # кто именно зависит от одного файла
```

Раньше в этом месте лежала таблица, скопированная из вывода команды. Она
устарела молча (у `config/index.ts` было записано 16 импортёров при 17 на диске)
и не покрывалась ни одной проверкой `verify`. Дублировать вычислимое — заводить
второй источник истины, который расходится первым; поэтому осталась только
команда и то, что из вывода не следует, — **почему** точка горячая:

- `shared/index.ts` (первое место с большим отрывом) — единственная дверь
  наружу из полок. Ширина здесь не дефект: барьер форка держится именно тем,
  что компонент не знает внутренней раскладки полки.
- Бочки `domain`, `config`, `state`, `context`, `motion` — намеренные швы слоёв.
  Правка **внутри** такой папки радиус не имеет; радиус имеет правка её
  публичной поверхности, и это ровно тот случай, когда сначала смотрят `blast`.
- `public-api/types.ts` и `Diagnostic/types.ts` — типы, а не код: их радиус
  проверяет компилятор, и он же его чинит.

**Файлы, которые не импортирует никто (не-тестовый код):**

| Файл | Статус |
| --- | --- |
| `data-gen/index.ts` | программный API папки, объявленный в её шапке (`runDataGen` / `generateSlides` / `buildSlide`); по графу мёртв, существует ради переноса — тот же случай, что барьер форка |
| `data-gen/cli.ts` | точка входа npm-скрипта — ожидаемо |
| `main.tsx` | точка входа приложения — ожидаемо |

| `vite-env.d.ts` | ambient — ожидаемо |

## D. Мёртвые экспорты (проверено грепом, не эвристикой)

Разделены по смыслу — не всё «мёртвое» подлежит удалению.

### D1. Пусто — и это не случайность

Здесь был список транзитных реэкспортов, которые никто не импортировал: два в
`motion`, четыре в `presentation`, один в `slides`, три в `domain` и дубль
`default` в бочке диагностики. **Они удалены, а не описаны.** Раздел оставлен
пустым намеренно: место, куда можно положить известный дефект, рано или поздно
им наполняется. Найденное чинится, а сюда попадает только то, что осталось
жить по причине — и тогда ему место в D2 или D3.

Ждавшая решения `client/modules/index.ts` удалена: бочка была мёртвой и
неполной, а общий корень импорта для модулей ещё и опасен — он втянул бы
диагностику в граф каждого потребителя.

### D2. Мёртвое внутри форка

- `shared/clientState/media/useMedia/internal/useOrientation.ts` →
  **сам хук `useOrientation` не вызывается никогда.** Форку нужны только
  константы `PORTRAIT_ORIENTATION_QUERY` / `LANDSCAPE_ORIENTATION_QUERY`;
  вместе с хуком в форк тянется и импорт `useMediaQuery`.
- `shared/clientState/media/useMedia/internal/resolveActiveBreakpoint.ts` →
  `STANDARD_BREAKPOINTS` (в форке не нужен, оси задаёт карусель).
- `shared/engines/kinetic/internal/motion/index.ts` → 14 реэкспортов, которых
  фасад не касается; `internal/gesture/index.ts` → 4.
  **Это НЕ мусор:** барьер форка обязан быть полным, чтобы папка выносилась
  копированием. Трогать нельзя.

### D3. Публичная поверхность — не трогать

- `client/index.ts` и `public-api/index.ts` отдают оба набора ключей
  (`CLASS_NAME_KEYS`, `SLIDE_CLASS_KEYS`) и оба типа ключа. Значения живут
  через `public-api/types` напрямую, реэкспорты — контракт для хоста. Асимметрия
  (`CLASS_NAME_KEYS` был только в `public-api`, хотя `ClassNameMap` ключуется
  именно им) снята: точка входа пакета обязана отдавать ключи той карты, которую
  требует заполнить.
- `shared/theme/index.ts` → `ThemeStateProvider`, `THEME_MODES` — заявленный
  публичный API коробки (README описывает «Mode B» на `ThemeStateProvider`).
- Экспортируемые типы без потребителей (`GoToPlan`, `ModuleRenderPolicy`,
  `PaginationWidgetBinding`, `CoastedLaunchInput`, …) — часть читаемого
  контракта модуля.

## F. Утверждения доков, которые код не выражает сам

> **Статус этого раздела: заявки, а не факты.** Ниже — то, что документация
> проекта утверждает и чего из кода не видно. Часть заявок опирается на прошлые
> прогоны разработки и замеры, сделанные до нас. Мы их **не наследуем как
> авторитет**: каждая проверяется заново, когда до неё дойдёт дело. Держать в
> голове стоит не вывод, а **место, где он может выстрелить** — чтобы правка
> не прошла мимо непроверенного допущения молча.

- **ADR-001** — `reconcileStateToLayout` применяется РОВНО в двух точках
  (проекция в рендере + вход каждой команды) и обязан быть **идемпотентным**;
  это жёсткий контракт, закреплённый тестом.
- **ADR-002** — все входы caller-owned. Никакой валидации/нормализации в
  проде **нигде**, включая перерасход долей профиля. Diagnostic только
  наблюдает.
- **ADR-003** — почему не `transition: transform`: (1) профиль accel/cruise/decel

- **`shared/README.md:23-25`** — «каждая заготовка держит свои копии хуков; **то,

  про запрет модульного состояния как такового. `useIsTouchDevice` и

- **`shared/engines/gesture/README.md:21`** — «**Touch pointers only** (mouse/pen

## H. Решения по объёму (приняты разработчиком)

1. **Стенд правим только по необходимости.** `App.tsx`, `App.module.scss`,
   `globals.scss`, `index.html`, данные в `public/` трогаем лишь тогда, когда
   этого требует правка в компоненте или на полках. Их собственные
   шероховатости идут отдельным списком «к сведению», не в план:
   - `App.tsx:35-40` — чтение `window.location.search` на модульном уровне
     (SSR-враждебно, вычисляется при импорте);
   - `App.module.scss` — сырые `@media` вместо осей (это хост, у него свои
     оси, — формально допустимо);
   - `alt: ""` у всех 12 слайдов в обоих `public/carousel-slides*.json`.

2. **ЗАКРЫТО — собственный стор у `useIsTouchDevice` и `useDataSaver` не дефект.**
   Ранее здесь стоял открытый вопрос: почему эти два хука держат модульный
   синглтон, а `useIsReducedMotion` делегирует в `sharedStore/useMediaQuery`.
   Разобрано, вопрос снят.

   `useMediaQuery` — мультиплексор «один слушатель на строку media-запроса», и
   больше он не умеет ничего. Два хука наблюдают источники, которые в
   media-запрос не выражаются:
   - `useIsTouchDevice` = `(pointer: coarse)` **ИЛИ** первый `pointerdown` с
     `pointerType === "touch"` (защёлка + снятие слушателя);
   - `useDataSaver` = `(prefers-reduced-data: reduce)` **ИЛИ**
     `navigator.connection.saveData` с её собственным событием `change`.

   `useIsReducedMotion` делегирует не потому, что «правильнее», а потому что он
   чистый media-запрос и ничего сверх. Всё это задокументировано таблицей в
   `environment/library/README.md:9-11`, включая цену делегирования: «rides
   `../../sharedStore/useMediaQuery` (**copy that folder too**)».

   Конвенция `shared/README.md` про **один `useMediaQuery.ts` на проект**, а не
   про запрет модульного состояния вообще. Собственный синглтон у хука с
   не-media источником её не нарушает.

   Замысел полок (подтверждён разработчиком): нужен один хук — копируешь только
   его, он самодостаточен; нужны все — берёшь фасад `useUserEnvironment`.
   Фасад стор не объединяет и не должен: три сигнала смотрят в три несвязанных
   источника, объединять нечего. Байт-идентичность копий `library/*` и
   `useUserEnvironment/internal/*` — это барьер форка, то есть цель, а не
   дублирование по недосмотру. Обе ветки одновременно в один проект не берут.

3. **React Compiler не включаем; готовность к нему держим.** Решение разработчика:
   ручная мемоизация остаётся — «перебдеть дешевле, чем ловить редкие
   расхождения». Компилятор — не часть React 19, а отдельный плагин сборки
   (`babel-plugin-react-compiler`); в проекте его нет, `@vitejs/plugin-react`
   стоит без него.

   Цена включения, если решение когда-нибудь пересмотрят: в сборку возвращается
   Babel (сейчас она 733 мс без него), бандл подрастает на генерируемый код
   кэширования, появляется класс труднодиагностируемых расхождений «компилятор
   решил иначе». Выигрыш: два ручных кэша идентичности (`slideCache`,
   `laneCacheRef`) и часть `useMemo`/`useCallback` становятся не нужны.

   **Готовность — требование к правкам, а не фон.** Правила `react-hooks/*`,
   включая правила React Compiler, включены во всём репозитории; ослаблять их
   или гасить файлами нельзя. Те же правила защищают от StrictMode и
   Offscreen-рендера, а не только от компилятора. Полки в `shared/**` обязаны
   работать и с ним, и без него: их копируют в проекты, где решение может быть
   другим.

- само ограничение;
- на что оно влияет;
- что сломается, если его убрать.

Затронуто ~35 файлов. Правки — только в комментариях, документации и

Попутно исправлена мохибейка в трёх местах (`≤`, `≈`, `±`) — в `src` её больше

## J. Как перепроверить всё это одной командой

Скрипт анализа графа лежит в репозитории — `.context/graph.mjs`. Запускать из
корня репозитория (`c:\dev\CarouselCC`):

```
node .context/graph.mjs brief X  # досье на адрес: связи, тесты, все записи базы
node .context/graph.mjs cycles   # циклические импорты
node .context/graph.mjs blast    # радиус поражения + файлы без импортёров
node .context/graph.mjs dead     # экспорты, которые никто не импортирует
node .context/graph.mjs verify   # сверка базы с кодом, все девять проверок
node .context/graph.mjs twins    # правка форка: не забыт ли близнец
node .context/graph.mjs open     # гипотезы, дыры в тестах, узлы без якоря
node .context/graph.mjs sizes    # непустых строк на файл (в базе их нет)
```

Два ограничения инструмента, оба честные и оба видны в выводе:

1. Файл, из которого делают `export *`, из анализа мёртвых экспортов
   исключается — нельзя разобрать, что именно утянули.
2. Импорт **сразу после импорта-побочного-эффекта** не разбирается: в
   `main.tsx` строка `import "./globals.scss";` не имеет `from`, и разбор
   проглатывает следующую за ней строку целиком. Поэтому `dead` показывает
   `app/App.tsx → default`, хотя `main.tsx` его импортирует. Единственный такой
   случай в проекте; лечится перестановкой строк, но перестановка сместила бы
   порядок загрузки стилей, а это уже правка поведения.

`verify` делает десять проверок и падает, если провалилась любая:

| Что сверяется | Как |
| --- | --- |
| покрытие карты | каждый файл кода назван в `00-map.md` |
| покрытие тестов | каждый тестовый файл назван в `08-tests.md` |
| пометки `CONSTRAINT` | каждая пометка в коде описана в `07-invariants.md` |
| пометки решений | каждая пометка в коде описана в `09-decisions.md` |
| правила направления | таблица слоёв из `03-graph.md` сверена с графом импортов |
| якоря `file:line` | файл существует, номер строки не выходит за его длину |
| цитаты у якорей | цитата найдена на тех самых строках, куда указывает якорь |
| объявленный состав | `(N файлов)` у папки совпадает с диском; объём строк не заявляется |
| радиус поражения | «N импортёров (+M тестовых)» совпадает с графом импортов |
| ссылки на документацию | каждый путь `*.md`, названный в комментарии кода, ведёт в существующий файл |
| копия инструмента | `graph.mjs` на полке правил совпадает с рабочим байт в байт |

Три послабления, все намеренные. Файл засчитывается упомянутым по имени с
расширением **или** без него — база пишет и полными именами, и группами вида
`{a,b}.ts` (группы раскрываются). Ambient-объявления (`*.d.ts`) из покрытия
исключены: в них нет ни поведения, ни связей. Состав папки считается по коду без
тестов, а если в пути есть `tests` — наоборот, только по тестам.

Чего инструмент **не** видит: число, записанное прозой или в форме, которой нет
в README базы. Такое число молча остаётся непроверенным — поэтому размеры пишут
только тремя объявленными формами.

## K. Ловушки окружения (собраны на практике)

Не про код проекта, а про инструменты, которыми его правят. Каждая уже стоила
времени.

1. **Все файлы в рабочем дереве — CRLF** (`core.autocrlf=true`, в индексе LF;
   с версии `.gitattributes` политика зафиксирована как `eol=lf`). Отсюда:
   любая замена многострочного фрагмента, которая ищет по одному лишь символу
   перевода строки (LF), **не найдёт ничего**. Читать файл, нормализовать концы
   строк, править, писать обратно в том же виде. Однострочные замены проходят
   и без этого — и тем опаснее, потому что создают ложное ощущение, что метод
   работает.

2. **`node -e` в этом окружении теряет один уровень экранирования.** Строка
   «обратный слэш плюс s» доезжает до JS уже без слэша, то есть как обычная
   буква — поиск по такой строке молча не находит ничего, и это выглядит как
   «в файле нет искомого». Лечится так: скрипт пишется в файл (heredoc с
   закавыченным разделителем) и запускается как `node file.mjs`, а в поисковых
   строках экранирования лучше не иметь вовсе — искать по фрагменту без него.
   Тот же эффект бьёт и по heredoc, поэтому проверять надо результат, а не
   намерение.

3. **`grep` с диапазоном `[а-яА-Я]` в этой локали срабатывает на тире и
   эмодзи** — сравнение идёт побайтно. Проверка «есть ли в коде кириллица» так
   даёт сотни ложных срабатываний. Считать по кодовым точкам
   (`0x0400–0x04FF`), а метод сверять на файле, про который заранее известно,
   есть там кириллица или нет.

4. **Prettier ломает многострочный комментарий внутри JSX-тернарника**: склеивает
   строки в одну и переставляет куски местами, а результат не идемпотентен —
   `--check` остаётся красным после `--write`. Единственное известное место —
   `SlideItem.tsx`, где объяснение теперь вынесено НАД выражением. Если такой
   комментарий появится снова, чинить так же, а не подгонять форматтер.

5. **PowerShell-синтаксис here-string (`@'…'@`) в Bash не работает** — попадает
   в текст как есть. Сообщения коммитов писать во временный файл и передавать
   через `git commit -F`.
