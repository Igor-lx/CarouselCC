# 08-tests — что пиннит каждый тест

Не «что тестируется», а **что закричит, если сломать**. Для рефактора это
главный вопрос: какой файл упадёт и о чём это скажет.

**Заполняется послойно.** Ниже — разобранные слои.

## B. `client/config/**` — собственных тестов нет

Слой не покрыт ни одним тестом напрямую, и это не пробел: проверять в нём нечего,
кроме сборки объекта. Значения косвенно закреплены в двух местах:

- `modules/Diagnostic/checks/constantChecks.ts` и его тесты — сверка
  опубликованных значений с реальными;
- `client/tests/carouselContract.test.tsx` — держит `REPEATED_CLICK_VISUAL_LOOKAHEAD_PAGES`
  вместе с поведением, которое от него зависит.

Что **не** закреплено ничем: `withDefault` пропускает `-1`, `0`, `NaN` и строку
там, где ждут число. По ADR-002 это осознанно, но тестом не зафиксировано —
значит и не заметит, если однажды кто-то решит «добавить валидацию».

## C. `client/domain/tests/**` — 9 файлов / 873 строки, ни одного рендера

| Файл | Что закреплено |
| --- | --- |
| `math.test.ts` (28) | `mod` на отрицательных и `total <= 0`. Прямо сказано, что `clamp` намеренно **не** тестируется: он проверяется через результат у вызывающих |
| `layout.test.ts` (173) | геометрия страниц целиком: клампинг размера страницы, округление последней страницы вверх, `virtualLength` в цикле против finite, `dataKey` меняется по идентичности слайдов и не меняется от размера страницы, пустая колода без деления на ноль. Отдельный блок — «`pageContaining` (floor) против `nearestPageIndex` (round)», включая тест «они расходятся намеренно». Плюс `alignedVirtualIndex` (ближняя полоса, не нулевая) и пропорциональный `reconciledPageIndex` |
| `renderWindow.test.ts` (129) | буферное окно **всегда** содержит сегмент (перебор пяти пар, включая дробные и обратные), буфер по целым экранам с каждой стороны, цикл не клампится, finite клампится в данные, нескользящая колода рендерит саму себя, пустая даёт вырожденное окно. `expandWindow` только расширяет — это и есть «слайд не пропадёт посреди поездки» |
| `visibility.test.ts` (90) | дробное удержание оставляет активными **все** слайды на экране, для N = 1…6; `isActual` при этом остаётся ровно один — `aria-current` не размывается; во время поездки активны и стартовая, и целевая страницы |
| `deckPadding.test.ts` (112) | доклад до целых страниц: уникальность ключей (перебор пяти колод), клон переиспользует **данные**, но не идентичность, `layoutIndex` остаётся плотным рядом (на нём держится `aria-label`), докладу никогда не нужно больше фиксов, чем слайдов (перебор 12×12), и — идентичность массива при целой колоде, чтобы не рвать мемо потребителей |
| `dragRelease.test.ts` (112) | контракт отпускания: от покоя решает геометрия; при перехвате летящей поездки — **нажатая** страница, а не ближайшая, и это не snap, а нормальный шаг; без замера нажатия — цель поездки; явный свайп перебивает всё |
| `measureSlotSize.test.ts` (73) | единственный тест слоя с `jsdom`: слот = (ширина + зазор) / число слайдов; отсутствующий и непарсящийся зазор дают ноль, а не `NaN`; явно переданная ширина не заставляет перечитывать бокс; ноль слайдов и схлопнутый вьюпорт дают 0; фолбэк на `--gap` |
| `renderedImageSrc.test.ts` (122) | выбор URL: самый широкий кандидат по `w`, сканируются **все** наборы, при равной ширине выигрывает первый (default), в single-set режиме приоритет у `defaultSrc` издателя, не-строковый `content` картинкой не считается |
| `track.test.ts` (34) | трансформ считается от `layoutOrigin`, а не от нуля: одинаковая разница даёт одинаковый сдвиг; полоса инвариантна к сдвигу опоры — на этом держится «редкая ре-базировка никого не двигает» |

**Чего в слое не закреплено:** `laneDistanceFromBand` не имеет собственного
теста — его поведение проверяется только косвенно, через потребителей
(`useSlideFetchReach`).
